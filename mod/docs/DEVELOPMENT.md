# Разработка Azeroth Survivors mod

Все команды Python ниже выполняются из каталога `mod/`. Нужны Python 3.11+
x64, оригинальный EXE и зависимости из `requirements.txt`. Запускать игру
для офлайн-проверки сигнатур не требуется.

## Структура

| Путь | Назначение |
|---|---|
| `launcher.pyw` | Проверка сборки, синхронизация прогресса, установка переводов и запуск |
| `patch_azeroth.py` | Патч на 52 очка, загрузка модулей, секции `.modtxt`/`.moddata`, сборка и отчёты |
| `offsets.py` | Проверка PE x64, AOB, RIP/rel32, указатели, поля структур и MSVC RTTI |
| `patches/*.py` | Отдельные модули с `patch(p)`, применяются по имени файла |
| `patches/quest.lua` | Логика и интерфейс заданий; встраивается `patches/quest.py` |
| `pvp.py` | Онлайн-окно, игровой feed, синхронизация коопа, события матчей и слияние профиля |
| `choice_shield.py` | Чистая модель таймеров защиты и выбора владельца врага |
| `save.py` | Чтение/запись сохранений, общий прогресс и слияние результатов матча |
| `bans.py` | Сохранение запретов дополнительных предметов |
| `lang/en.json`, `lang/ru.json` | Плоские переопределения строк; ключи и `{v}` сохраняются |
| `tools/` | Офлайн-проверки, дамп адресов и сборка распространяемого архива |
| `server/` | Cloudflare Worker, SQLite Durable Object `Hub`, API и страница наблюдения |

В локальном рабочем пространстве могут быть несколько checkout одного
репозитория с разными ревизиями. Перед изменениями проверь `git status` и
`git log -1` именно в выбранном checkout; игровые EXE и локальные профили
не являются исходниками мода.

## Сборка и совместимость

```powershell
python -m pip install -r requirements.txt
python tools/check_versions.py ..\AzerothSurvivors.exe
python patch_azeroth.py ..\AzerothSurvivors.exe
```

Патчер создаёт `AzerothSurvivors-52.exe` рядом с переданным оригиналом.
Исходный EXE не перезаписывается. `apply_patches(p)` выполняет поиск и
применение всех патчей в памяти; запись результата начинается после проверок.
Места изменения кода определяются сигнатурами, а не фиксированными VA.

Для нескольких сохранённых оригиналов:

```powershell
python tools/check_versions.py
python tools/check_versions.py ..\versions\AzerothSurvivors-109.exe ..\AzerothSurvivors.exe
```

Без аргументов checker ищет `../versions/*.exe`. Если файлов нет, он
возвращает ошибку. Он продолжает проверку после отказа отдельного патча
и выводит ошибки и необязательные отключения. Код 0 означает отсутствие
ошибок патчей, но сообщения `(off)` также нужно просмотреть. Для проверки
финальной компоновки дополнительно выполни саму сборку.

Храни оригинальные версии вне Git. Ветка с изменениями должна сохранять
совместимость с доступными оригиналами либо явно документировать границу.

## Автоматическое восстановление адресов

`Patcher.offsets` содержит `OffsetResolver` для исходного PE. Патчи коопа,
квестов, иконок и шаблонов врагов потребляют найденные значения напрямую.

| Механизм | Реальное поведение |
|---|---|
| AOB | Маски `??`, `?`, `4?`, `?F`, поиск в границах секций, структурный validator и альтернативные паттерны; неоднозначность вызывает `PatchError` |
| RIP/rel32 | Capstone декодирует инструкцию, вычисляет целевой адрес и проверяет отображение/тип секции; произвольный disp32 сам по себе ссылкой не считается |
| Pointer chains | `pointer_chain(read, root, offsets, final_offset=...)` делает точные u64-чтения с пределом глубины; `follow_pointer` ограничен файловым образом |
| Схема полей | `field(...)` проверяет базовый/индексный регистр, ширину и согласованность смещения, сохраняет байты инструкций |
| RTTI/vtable | Проверяются MSVC x64 COL, TypeDescriptor, иерархия и исполняемые адреса методов; это статические кандидаты, не идентификация живых объектов |
| Дамп | После успешной сборки автоматически сохраняется `<имя EXE>.offsets.json` |

Для цепочки указателей сначала читается `*root`; каждый элемент `offsets`
прибавляется перед следующим разыменованием; `final_offset` прибавляется
без чтения. Виртуальные нулевые хвосты секций могут быть целью адресной ссылки,
но не выдаются за прочитанные из файла байты. Динамический heap отсутствует
в EXE; модуль сам не подключается к процессам.

Отчёт содержит версию формата, SHA-256/размер оригинала, предпочтительный
ImageBase, RVA функций и глобальных данных, поля, цепочки, принятые ссылки,
RTTI-кандидаты, хеш исходников сборки и хеш результата. Реальные адреса при
ASLR получаются прибавлением RVA к фактической базе модуля.

`is_current` сверяет отчёт с исходным EXE, хешем сборки, результатом и
`.feed.json`. Отсутствующий, повреждённый или устаревший отчёт вызывает
пересборку. Старый дамп не используется как источник адресов нового EXE.

Native reflection игровых классов пока не подтверждена. В проверенном
оригинале с SHA-256 `dc10453398ceb398076f6d3b6ac7859470de2ff7ccd68ac1d00a02f9f1e5209a`
получены 23 адреса, 12 полей, 12 цепочек и одна служебная RTTI-таблица
`type_info`. Это результат конкретной сборки, а не обещание для будущих версий.

Для самостоятельного отчёта укажи новый выходной файл:

```powershell
python tools/dump_offsets.py ..\AzerothSurvivors.exe --output ..\offsets-diagnostic.json
```

Команда применяет все патчи в памяти и записывает только JSON. Игра не
запускается, готовый EXE не записывается, существующий отчёт не заменяется.
Изменение ABI или алгоритма всё ещё может требовать адаптации сигнатуры.

Форматы: [Microsoft C++ ABI в LLVM](https://llvm.googlesource.com/llvm-project/clang/+/refs/heads/main/lib/CodeGen/MicrosoftCXXABI.cpp),
[Capstone Python API](https://www.capstone-engine.org/lang_python).

## Проверки

Проверки Python без запуска игрового процесса:

```powershell
python tools/test_offsets.py
python tools/test_coop_sync.py
python tools/test_coop_network.py
python tools/test_lan_server.py
python tools/test_launcher_network.py
python tools/test_choice_shield.py
python tools/test_choice_integration.py
python -m unittest tools.test_coop_choice_cast -v
```

Для эмуляции нативных хуков нужны оригинальный EXE и дополнительная
зависимость `unicorn`, которая не входит в обычный `requirements.txt`:

```powershell
python -m pip install unicorn
python tools/test_choice_native.py ..\AzerothSurvivors.exe
python tools/test_choice_push.py ..\AzerothSurvivors.exe
python tools/test_coop_choice_cast_native.py ..\AzerothSurvivors.exe -v
python tools/test_coop_ledger_native.py ..\AzerothSurvivors.exe
python tools/test_feed_native.py ..\AzerothSurvivors.exe
```

Тесты нового resolver используют искусственные PE-фикстуры и не требуют
игровых файлов. Нативные тесты используют Unicorn; запуск/подключение к игре
им не нужны. Офлайн-тесты не подтверждают визуальное поведение или
синхронизацию двух реальных клиентов: для изменений интерфейса и коопа
нужна отдельная проверка в игре. Перед испытаниями прогресса сделай резервную
копию сохранения.

Защита выбора проверяет фазу 2 непосредственно на входе в обработчик урона,
включая временную фазу `FAKED`; неуязвимость ограничена пятью секундами от
начала окна выбора по `REAL_T`, независимо от таймеров «Прикрытия».
`patches/coop_choice_push.py` вызывается после игрового тика и восстановления
фазы. Он отслеживает закрытие локального/свежего удалённого выбора в свободных
полях +148/+152 блока `AZSCHOI1`, исключает особых врагов и отправляет штатный
пакет движения. Все адреса внутри cave вычисляются относительно RIP/блока;
новых абсолютных указателей без ASLR relocation нет.

Запускатель показывает окно подготовки, пока работает патчер. В переносимой
сборке ошибки и сведения о запуске записываются в
`%LOCALAPPDATA%\AzerothSurvivorsMod\launcher.log`. Для проверки запускателя:

```powershell
python tools/test_launcher_progress.py
python tools/test_runtime_stub.py
python tools/test_quest_lua.py
python tools/test_auto_update.py
python tools/test_release_contract.py
```

Патчер передаёт этапы через необязательный callback `main(progress=...)` /
`apply_patches(p, progress=...)`. Запускатель пишет их в журнал сразу, поэтому
длительный поиск не скрывается до окончания всей сборки. Проверку первой сборки
нужно выполнять на копии игры без готового `.source-sha256`: повторный запуск
уже актуального EXE не проверяет медленные участки патчера.

При поиске Lua-чанка используется `bytearray.startswith(prefix, offset)`:
срез `data[offset:]` создавал большую временную копию для каждого кандидата.
Тест квестового патча ограничивает суммарный объём таких чтений на фикстуре.

Автообновление реализовано в `auto_update.py` и `apply_update.ps1`. Помощник
PowerShell хранится в UTF-8 с BOM для Windows PowerShell 5.1. Он ждёт завершения
запускателя, переносит только `mod` и четыре известных корневых файла, сохраняет
один проверенный backup и откатывает установку при ошибке. Рабочие Git-копии
пропускаются. Тесты блокируют файл для проверки отката; обычная сетевая ошибка
не блокирует запуск установленного мода. `AZS_SKIP_UPDATE=1` отключает проверку
в изолированных тестах и при автоматическом перезапуске после обновления.

Для публикации совместимого с автообновлением пакета сборщик поддерживает
`--version YYYY.MM.DD.N-<short-sha> --game <original-exe>`: создаются ZIP с
идентификатором игры, `VERSION`, `RELEASE.json`, лицензии и `.zip.sha256`.
Загружай ZIP и checksum в один стабильный GitHub Release в публичном
`VladXon/azeroth-survivors-mod-releases`: это адрес из `auto_update.REPOSITORY`.
Приватный репозиторий исходников не используется для клиентских загрузок.
Номер `N` увеличивается для каждого выпуска за один день, даже при смене SHA.
Режим без `--version`
сохраняет промежуточный архив по SHA для разработки.

Команды сервера и его интеграционные тесты описаны в
[server/README.md](https://github.com/Anfi1/azeroth-survivors-mod/blob/main/server/README.md).

## Добавление предмета

1. Добавь `Jewel(...)` в `patches/custom_jewels.py:JEWELS`: ID, английское имя,
   строку эффекта с `{v}`, иконку, базовое значение, слот и эффект.
2. Используй `difficulty`/`thorns` либо реализуй соответствующий эффект.
   Дополнительные предметы имеют kind 0, поэтому штатный switch бонусов
   сам по себе их эффект не применяет.
3. Для вида в панели персонажа нужен display ID. Если иконки нет в штатной
   таблице, добавь lowercase-имя в `DISPLAYS` файла `custom_jewels_icons.py`.
   Отсутствие необходимого ID останавливает сборку.
4. Добавь `jewel.<id>` и перевод строки эффекта в `lang/ru.json`, при
   необходимости — в `lang/en.json`. Сохрани placeholders.
5. Система запретов охватывает до 32 дополнительных предметов. ID должны
   оставаться стабильными: `bans.py` сохраняет запреты по ID.
6. Выполни проверки совместимости и сборку. В игре проверь кодекс, карточку
   выбора и панель персонажа.

## Сборка архива

```powershell
python tools/build_release.py
```

Сборщик использует **только закоммиченное состояние `HEAD`** через `git archive`.
Незакоммиченные исправления в архив не попадут. При отсутствии PyInstaller
скрипт устанавливает его; также нужны инструменты `git` и `tar`.

Результат: `release/AzerothSurvivors-mod-<sha>.zip`. В него входят исходники
мода, `mod/VERSION`, среда `mod/runtime/AzerothSurvivorsMod.exe`, два BAT-файла
и инструкция `ПРОЧИТАЙ - мод.txt`. Сервер и `tools/` в пользовательский
архив не включаются. Среда запускает соседние Python-исходники мода.

Игровые EXE, сохранения, токены, локальные профили и сгенерированные отчёты
не должны попадать в Git. Перед сборкой проверь `git status` и содержимое
коммита. Создание архива не публикует GitHub Release и не развёртывает сервер.

## Лаунчер и выпуск релиза

`Azeroth Launcher.exe` — единственный файл GitHub Release. Он содержит Python,
pywebview, зависимости мода, 7-Zip (`7z.exe`, `7z.dll`, лицензия в `licenses/`)
и интерфейс `tools/launcher_ui/` (HTML + Tailwind CSS). Мод в EXE не входит:
лаунчер скачивает файлы `mod/` из публичного репозитория
`VladXon/azeroth-survivors-mod-releases` по тегу версии и сверяет каждый с
SHA-256 из `latest.json`. Логика без интерфейса — `tools/launcher_core.py`,
окно — `tools/azeroth_launcher.py`, офлайн-проверки — `tools/test_launcher_core.py`.

После правок `index.html`, `app.js` или `input.css` пересобери CSS:

```powershell
cd tools\launcher_ui
npx tailwindcss@3.4.17 -c tailwind.config.js -i input.css -o tailwind.css --minify
```

Выпуск (только из закоммиченного `HEAD`; версия `YYYY.MM.DD.N-<sha HEAD>`):

```powershell
python tools/build_launcher.py --version 2026.10.23.5-<sha>
python tools/publish_release.py --version 2026.10.23.5-<sha> --public <клон публичного репозитория> `
    --launcher "release\Azeroth Launcher.exe" --tested-game <SHA-256 проверенного AzerothSurvivors.exe>
```

Затем в клоне публичного репозитория: коммит `mod/` и `latest.json`, тег
`v<версия>`, push и `gh release create` с единственным файлом
`Azeroth Launcher.exe` (GitHub называет ассет `Azeroth.Launcher.exe`).
Переменные `AZS_MANIFEST_URL`, `AZS_FILE_URL`, `AZS_ASSET_URL`, `AZS_GAME_URL`
и `AZS_7Z` подменяют адреса и 7-Zip для проверок до публикации.

Пакеты прежнего формата (ZIP с BAT-файлами) больше не выпускаются. Их
встроенный updater, не найдя ZIP в релизе, продолжит запускать установленную
версию; для перехода игроку нужно один раз скачать лаунчер.
